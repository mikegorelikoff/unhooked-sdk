# Verification and repeatability

A validation result describes the draft. An export report describes the generated bytes. A live verification receipt records what happened in a configured host test. Read these results together when deciding whether a skill is ready to use.

## Check a package

1. Save the composed draft, target profile and file digests from the SDK.
2. Ask the agent to run the configured case with the exact package in a fresh host session.
3. Check the receipt for its case, session, expected and observed test outcomes and package digests. If the host cannot run, the SDK can return `not_run`.
4. For a repeatability check, run the same structured draft and case independently and compare the two passing receipts. The sessions must be distinct. The full digest maps, test identity and observed outcomes must match.

The same draft, target and SDK version produce the same export bytes. Asking a model to author new text again can produce a different draft, even from the same prompt.

## What the checkout example showed

- HX loaded all three step files and advanced from start to completion.
- The Python helper returned 0 for matching amounts, 1 when the charge was 499 cents and expected was 0, and 2 for invalid input.
- A separate checkout skill using the same package layout was installed by BMAD 6.12.4. A fresh agent found it through the BMAD help catalog, read the steps in order and ran the installed script.

The [public checkout script](Examples.md#run-the-exported-checkout-helper) compares two supplied amounts. The [recorded demo](Demo.md) shows a different check that reproduced a shipping regression against a test fixture.
